# /exec-plan — PRO.MD 计划执行器

按步骤执行项目中的 PRO.MD 计划，每步完成后自动跑验证，确认无误后再继续。

## 使用方法

```
/exec-plan                    # 列出所有步骤，从第一个未完成的步骤开始
/exec-plan step 3             # 从第 3 步开始执行  
/exec-plan resume             # 从上次中断的地方继续
/exec-plan status             # 查看当前进度
```

## 执行流程

对于每一个待执行的步骤，遵循以下流程：

### 1. 找到 PRO.MD 计划文件

- 先在当前工作目录找 `PRO.MD`
- 再在项目根目录 `../PRO.MD` 找
- 如果找不到，询问用户路径

### 2. 解析当前步骤

读取 PRO.MD，识别：
- 已完成的步骤（标记 `✅` 或 `[x]`）
- 当前待执行的步骤（无标记或 `[ ]`）
- 步骤的验证条件（如果有明确写出的 build/lint/test 要求）

### 3. 执行步骤

- 明确告知用户当前执行的步骤编号和标题
- 执行该步骤所需的所有代码修改（Edit/Write）
- 如果有多个文件需要修改，一次完成，不要分多次

### 4. 运行验证

执行完成后，立即运行验证命令：

```bash
# 前端项目验证
npm run type-check
npm run lint
npm run build-only
```

如果验证失败：
- 读取错误信息，分析根因
- 修复问题
- 重新验证，最多重试 3 次
- 3 次后仍失败，停止并报告

### 5. 标记完成

验证通过后：
- 在 PRO.MD 中该步骤前添加 `✅` 标记
- 记录步骤完成摘要

### 6. 询问是否继续

```
步骤 N「步骤标题」已完成 ✅
  修改文件: file1.ts, file2.vue
  验证: type-check ✅ | lint ✅ | build ✅

继续下一步 N+1「下一步标题」？(y/n)
```

- 用户同意 → 继续执行下一步
- 用户拒绝 → 输出当前进度摘要，结束

## 当前进度报告格式

```
⬜ 步骤 5: 响应式布局优化
```

## 注意事项

- 不要一次性执行多个步骤，除非用户明确要求 "run all"
- 如果某一步骤有子步骤，按子步骤粒度执行（但同一子步骤内的多文件修改要一次完成）
- 如果 PRO.MD 引用其他文件（如 ACCEPTANCE.md），一并读取作为参考
- 不要修改 PRO.MD 中未要求修改的内容
